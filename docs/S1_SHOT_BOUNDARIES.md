# S1.3 镜头边界与关键帧

## 这一阶段在做什么

输入是一段连续视频，输出是两层更适合 Agent 使用的结构：

1. 镜头（shot）：两次剪辑转场之间的一段连续画面。
2. 关键帧（keyframe）：每个镜头时间中点的一张代表图片。

当前基线使用 FFmpeg 的 `scene` 分数。相邻画面变化超过阈值时，把当前帧当作新镜头的第一帧。阈值越低越敏感，镜头会切得更多；阈值越高越保守。

## 为什么先做简单基线

这一步先固定完整的数据接口和验收方式：

- `shots.jsonl`：每个镜头的起止时间、持续时间、转场分数、关键帧时间和路径。
- `summary.json`：算法、阈值、视频信息和镜头时长统计。
- `keyframes/`：逐镜头中点帧。

后面可以把边界检测器替换成 TransNetV2，而下游视觉理解、检索和奖励计算不需要改数据格式。

## 复现命令

```powershell
python scripts/detect_shots_ffmpeg.py `
  data/processed/tears_of_steel/s1/video_only.mp4 `
  data/processed/tears_of_steel/s1/shots_ffmpeg_t035 `
  --threshold 0.35
```

## 当前关键帧策略的限制

时间中点帧可解释、稳定，但不一定是内容最丰富的一帧。例如中点可能正好是模糊运动帧。后续可让视觉 Agent 在镜头内对多张候选帧评分，再通过 RL 学习在“信息量”和“调用成本”之间取舍。

## 本次样本结果

- 视频时长：480 秒，24 FPS。
- 阈值：0.35。
- 检出转场：97 个。
- 得到镜头/关键帧：98 个。
- 镜头时长：最短 0.5 秒，中位数 3.0 秒，平均 4.90 秒，最长 37.21 秒。

关键帧总览位于 `shots_ffmpeg_t035/keyframes_contact_sheet.jpg`。人工检查可见：快速动作段存在合理的短镜头，普通对话段保留了连续的正反打镜头；没有出现大面积黑帧，也没有明显由字幕单独触发的密集误切。因此 0.35 可作为当前 baseline 阈值，但它不是已学习的最优阈值。

## 与 TransNetV2 的替换边界

以后只替换“视频 -> 转场时间戳与置信度”这一段。新的检测器仍输出 `(timestamp, score)`，继续调用 `build_shots()`，下游 `shots.jsonl`、关键帧和 Agent 接口保持不变。
